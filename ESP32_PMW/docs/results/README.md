# Experimental results

Every file here is an **output**. Each is regenerated by the script named below,
so nothing here is a source and nothing here needs to be preserved by hand.

`flights/` is gitignored: it is 628 MB of video and grows with every take. Everything
else in this table is tracked, so a change to it shows up in `git status` and gets
committed with the run that produced it.

| directory | generated by | from |

## What a flight directory holds

`flights/<date>_<time>/` — written by `camera/record.py`, read back by
`record.open_recording` and `record.read_index`:

| file | written by | note |
|---|---|---|
| `A/A.mp4`, `B/B.mp4` | `FlightWriter.add` | one per camera, in calibrated order |
| `frames.csv` | `FlightWriter` | per-camera capture times. Without it every pair has to be assumed simultaneous, which costs 1.5-2.2x the lateral noise floor (`pose/theory.md` 17) |
| `meta.json` | `FlightWriter.close` | mode, fps, frame count, drops, skew stats |
| `A/background.png`, `B/background.png` | `pose/background.py` `for_flight` | optional saved plate, built on demand |
| `demo.mp4` | `pose/demo_video.py` | optional overlay render |
| `poses.csv` | `live_viz.from_recording(csv_out=...)` | optional solved trajectory |

Two shapes of take are on disk and both still read. Takes before 2026-08-30 have a
`frames.csv` with `# skew_*` comment lines above the header and a `meta.json` carrying
`camera_indices` / `rotate180`; later ones have neither. `read_index` passes
`comment="#"` and the `meta.json` readers use `.get()`, so nothing needs rewriting —
`camera/test_record.py` pins both. Eight takes were aborted before `meta.json` landed;
readers skip them rather than crashing.

## Calibration products the pipeline loads

These live next to the code that loads them, because that is where the loaders default:

- `controller/calib/assets/camera_intrinsics.npz` — `estimator.load_intrinsics()`
- `controller/calib/stereo_rig.json` — `rig.StereoRig.load()`
- `controller/calib/tilt_calibration*.json` — `shape.TiltCalibration.load()`

`stereo_calibration/` above is the *output* of a calibration run (coverage plots,
per-camera intrinsics); the files listed here are the ones the live pipeline reads back.
